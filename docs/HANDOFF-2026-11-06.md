## 二、当前架构与数据流

1. GitHub Actions runner 抓源、探测、聚合、发布
2. Worker 调度 Actions、存储任务、提供管理 API / 公开 API
3. `state/lines.json`：线路状态（大文件，KV）
4. `out/catalog.json` + `out/index.json` + 频道 shard：发布目录
5. `state/pool.json`：线路池快照（premium / backup / candidate）
6. `state/pool-stats.json`：待测/待复测/待复活统计
7. D1 `task_state`：任务队列/历史；`runtime_state`：小状态
8. 订阅：`/sub/<token>.m3u`、`/epg/<token>.xml`，由 Worker 实时渲染或 runner 预生成

## 四、订阅导出：当前正确行为与坑

### 线路池模式

- `premium`：只导出 **质量确认** 的精品线路
- `premium_backup`：精品 + 备用
- `all`：精品 + 备用 + 候选（alive 但分辨率未确认）
- `custom`：仅从线路池「保存为订阅」产生的自定义 lineKeys 使用

代码位置：

- `packages/core/src/linePool.ts`：`buildPoolSnapshot`
- `packages/core/src/export/types.ts`：`lineDisplayName`
- `packages/worker/src/lib/playlist.ts`：`buildFromPool`

关键变化（2026-11-05/06）：

- 不限量时，候选线路不再混入 premium，单独放 candidate
- 新增 `all` 模式；旧订阅默认 premium，需要手动改为 all 才能包含候选
- 修改分类后必须重新跑探测/发布，重建 `state/pool.json`，否则旧快照仍是旧行为

### M3U 名称与播放器分组

**重要约束：M3U 播放器按显示名称分组。**

- 同一频道所有线路必须同名，播放器才会显示为一个频道、内部切换线路
- 当前 `lineDisplayName` 不再拼接地区后缀、来源、池、速度、分辨率
- 线路详情只在 IPTV Studio 前台可见，M3U 名称里看不到
- 若要线路备注，只能用不同名称 → 播放器会拆成多个频道；这是 M3U 标准限制
- 修改 M3U 模板后，旧订阅必须重新导入/刷新播放器

### 预览与实际一致性

- `/api/admin/subscriptions/:id/preview` 已改为调用实际渲染器 `renderSubscription`
- 之前预览走旧 catalog + 每源 3 条，导致 897 预览 vs 2218 实际；已修复
- 预览接口返回 `channels`、`lines`，订阅预览 Sheet 会显示实际条数
- 订阅卡显示配置摘要、令牌尾号、更新时间

### 2280 vs 2218 vs 897 的口径

- `2280`：发布目录 index 中所有 alive 线路
- `2218`：线路池实际导出（候选/备用/来源/质量策略会过滤）
- `897`：修复前预览走旧 catalog 路径 + 写死每来源 3 条，已废弃
- 预览修复后应与实际 M3U 一致；不要要求与 2280 完全相等

## 七、akiralereal/iptv 分析

仓库：https://github.com/akiralereal/iptv

- GPLv3，Node.js + Docker，约 1854 stars，v4.61.x
- 自托管 IPTV 聚合/分发系统：1000+ 频道、内置抓取模块、EPG、GUI、多用户令牌、M3U/TXT、代理/兼容模式
- 包含央视频、咪咕、B站、抖音、虎牙、斗鱼、各地广电、官方网页解析、公开直链、自定义订阅等
- 它不是 Android TV 播放器；仍输出 M3U，无法解决“同名分组 + 单线路备注”的标准限制

### 值得借鉴

1. **模块化源适配器**
   - 每个源独立开关/配置/健康/频道数/错误
   - 统一 fetch → normalize → validate
2. **源健康面板**
   - 最近同步、频道数、失败原因、自动降级
3. **EPG 覆盖与映射**
   - 多 EPG 源、缺失频道、未映射频道、官方节目表回退、手动映射
4. **订阅级代理策略**
   - 直连 / 清单代理 / 全代理，而不是全局中继
5. **频道编排后台**
   - 分组、拖拽排序、隐藏、批量重命名
6. **多配置档/设备令牌**
   - 每台电视/每位用户独立频道组合和 token
7. **抓取失效处理**
   - 签名过期自动刷新；频道/网页/API 改版需要更新模块
   - 自动重试不能修复平台改版/登录/地区限制

### 不建议照搬

- Node/Docker 架构（当前是 Cloudflare Serverless）
- 全部抓取模块（维护/封禁/法律风险高）
- 账号型/私有接口
- 直接复制 GPLv3 代码到非 GPL 项目

### 推荐试验

1. NAS/Docker 跑一套 akiralereal/iptv
2. 让其输出 M3U，IPTV Studio 作为普通采集源导入
3. 对比频道稳定性、EPG、OwnTV 分组、代理负载
4. 若明显更好，再考虑把它作为源站，IPTV Studio 保留线路池/快照/播放器
5. 若要内置，先做 1–2 个稳定公开 API 适配器，不要全量铺开

## 八、播放器/Android 方向

已评估：

- `OwnTV` = Android TV UI；`OwnTV_Mobile` = 手机/平板 UI
- `OwnTV_Core` = 共享库（数据库/解析/EPG/播放引擎）
- `OwnTV_libmpv` = mpv+FFmpeg AAR
- GPLv3；libmpv 包装 MIT、二进制整体 GPLv3
- 电视装 OwnTV，手机装 OwnTV_Mobile，Core/libmpv 不单独安装
- Stock OwnTV 支持 M3U/Xtream/Stalker；仍无法在 M3U 中显示单线路来源/池/速度/分辨率
- 要该效果需 fork Core 解析自定义属性 + TV UI 线路选择器；工作量大，不建议一上来做
- 备选：精简 Android TV App（Compose + Media3 + 我们的 JSON API），不 fork Core；需 Android 构建/真机测试
- Web/PWA 已被否：电视浏览器/H.265/遥控器效果不够

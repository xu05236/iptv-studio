# 待修问题（本地记录）

## 2026-11-11 强制结束任务被“迟到完成”覆盖

- **现象**：手动强制结束一个运行中的任务后，过一会儿监控面板又把它显示成「完成」；同时，系统此前已自动重试、派出了接替任务，结束一个又冒出一个。
- **证据**：
  - `task-mwbnik8q-ycul` 最终 `status=done`、`retryCount=2`，完成于 2026-11-11T05:11:39Z。
  - `task-mwbn764b-oonr`、`task-mwbncolr-b4wj` 被标记 `cancelled`，消息「已由重试任务接替（1/2、2/2）」。
- **根因**：
  1. `packages/worker/src/lib/tasks.ts` 的 `finishTaskCore` 只拦截 `status === 'cancelled'` 的迟到回报；被强制结束（`failed`）的任务没有保护，运行器稍后回报 `done` 时会把状态改回「完成」。
  2. `mutateTaskCore` 的强制结束分支只处理当前任务，不会停掉由自动重试生成的接替任务，所以“结束一个又冒一个”。
- **期望**：
  - 强制结束的任务保持「已结束」，之后的进度/完成回报一律忽略。
  - 强制结束时，若存在它的重试接替任务，一并结束（或至少给出明确提示）。
- **状态**：已记录，待修；未开始，未提交。

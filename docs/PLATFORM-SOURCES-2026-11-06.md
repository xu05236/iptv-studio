# 平台源适配器：央视频 / 咪咕 的可行性（2026-11-06）

> 背景：用户对央视频、咪咕有兴趣；此前任务清单把"全量平台抓取模块"列为不做。
> 本文把这两件事分开：**平台直播逆向**（B站/抖音/虎牙/斗鱼）继续不做；**央视频/咪咕**单独评估，
> 结论是"可做，但必须按 playlist 代理设计，且分风险等级"。

> **决定（2026-11-06）**：央视频 + 咪咕 一起做，已插入执行清单 **Batch 2.5**（放在 F6 + F2 之后）。

## 0. 一句话结论

- **央视频**：值得做。63 路公开频道（央视 21 + CGTN 6 + 剧场 3 + 卫视 31 + CETV-1 + 国学），
  JCE 时移接口给 1080p H.264，社区已有可用实现；对我们是"给现有 CCTV/卫视频道多加一条稳定线路"，
  不新增频道类型。
- **咪咕**：已排期做实验性适配器（Batch 2.5），但不宜进公共订阅。签名短时有效、可能地域/网络受限、体育独家版权风险高。
- **B站/抖音/虎牙/斗鱼**：继续不做——不是线性电视、DRM/反爬重、维护成本高、对 IPTV 价值低。

## 1. 为什么"全量平台模块"不能做

| 原因 | 说明 |
| --- | --- |
| 架构冲突 | 我们的模型是"抓一次 → 静态 M3U（直连 URL）→ 预渲染进 KV → 热路径零 CPU"。平台流的 URL **带短时签名**（分钟级），静态导出必失效，必须改成"每次请求现签/现拼清单" |
| 额度冲突 | 清单每次刷新 = 1 个 Worker 请求（播放器通常 6–10 秒刷一次）。1 个观众 ≈ 360–600 请求/小时；10 万/天只够约 200 观众小时。全量平台 = 大量频道 × 观众，直接把 Worker 请求打穿 |
| 稳定性 | 平台接口随 App 版本/风控随时变；社区项目靠持续维护。我们只有一个人维护，模块越多烂得越快 |
| 法务 | 平台条款普遍禁止抓取/转播；体育/影视内容有独家版权，风险远高于开路电视频道。公开订阅链接 = 再分发 |
| 价值 | B站/抖音/斗鱼是 UGC 直播，不是电视台线性频道；放进 IPTV 聚合器体验差（无 EPG、无固定频道号） |

## 2. 央视频：可行（推荐）

外部参考：[funwukong/ysp-live](https://github.com/funwukong/ysp-live)（纯 Python、Docker；只发清单、分片直连央视 CDN）。

技术形态：

- **JCE PidTimeShift**（`jacc.ysp.cctv.cn`）：截取时移窗口转成直播流，1080p H.264，延迟约 20 秒；52/63 路走这条。
- **bkliveinfo + cKey（TEA 签名）**：11 路（CCTV-11/12/14/15/16/17、16-4K、4K、风云/第一/怀旧剧场）JCE 返回坏域名时的备用协议。
- **4K HEVC**：需要设备注册签名，社区实现不含——**我们也不做**（浏览器 hls.js 播不了 HEVC，得不偿失）。
- 播放器**直连央视 CDN 拉分片**；代理只下发 m3u8 清单。这是关键：带宽不经过我们，Worker 只承担清单请求。

对我们意味着什么：

- 央视频频道与现有频道重复（CCTV/卫视），所以它是**给现有频道加"官方稳定线路"**，不是新频道。
- 这条线路的 URL 不能静态导出（时移窗口 + 可能带签名）→ 导出里放**我们自己的稳定地址**
  `/platform/ysp/<channel>.m3u8`，由 Worker 现拼清单，分片直连。
- 与 F3 的 `official` 线路同一处理：**不参与 alive 判定/不判死**，导出置顶。

## 3. 咪咕：可做但实验性（不推荐进公共订阅）

社区有单文件 PHP 实现（恩山论坛帖称 84 台、官方接口签名、长期稳定），也有聚合项目带咪咕源。
但要注意：

- 签名/播放凭证短时有效，必须现签；刷新失败就是黑屏，用户以为是我们坏了。
- 部分内容地域/网络限制（尤其体育），我们的 Worker 在海外边缘节点，能否稳定拉清单需要实测。
- **版权风险最高的一类**：咪咕握有大量体育独家版权，转播/再分发的法律风险显著高于开路央视。
- 结论：做成"实验性适配器"——默认关闭、单订阅显式开启、**不进公共订阅/不公开列出**、自备 Cookie（若有），
  并且明确标注"可能随时失效"。

## 4. 架构设计（复用 F2 的 playlist 模式）

```
播放器 ──GET──> /platform/<adapter>/<channel>.m3u8        (稳定地址，写进 M3U 导出)
                     │  Cache API 6–10s（多观众共享）
                     ├─ ysp:  调 JCE 时移接口 → 生成 m3u8（分片 URL 指向央视 CDN）
                     └─ migu: 现签凭证    → 生成 m3u8（分片 URL 直连）
播放器 ──GET──> 央视/咪咕 CDN 分片                          (不经过我们)
```

要点：

1. **导出里只放稳定地址**，不写签名（签名会过期，还会泄露配置）。
2. **Cache API 6–10 秒**：同一频道的多个观众共享一次上游调用。
3. **每 token 配额**（复用 F2 的配额机制）：超限 429，防止单人刷爆请求数。
4. **健康与降级**：适配器失败时返回 502 + 明确原因，播放器回退到普通线路（我们的线路池本来就有）。
5. **不进 alive 判定**：平台线路由适配器自报状态，不交给 Actions 探测（探测必然失败/误判）。

## 5. 额度影响（关键）

| 项 | 估算 |
| --- | --- |
| Worker 请求 | 每观众每 6–10 秒 1 次清单请求 ≈ 360–600 次/小时；Cache 6–10s 后 N 个观众共享 |
| Worker CPU | 解析 JCE JSON + 拼 m3u8，预计 1–3ms（< 10ms 限制），可接受 |
| 子请求 | 每次 1–2 个（上限 50） |
| KV | **0**（不落 KV；频道映射是静态表，随代码发布） |
| Actions | 0（不探测、不抓取） |
| 结论 | 个人/小范围（≤5 观众）完全可行；**不要公开推广**，否则 10 万/天会在几小时内耗尽 |

## 6. 法务与合规（需要你拍板）

- 央视开路频道：信号本身免费公开，但"通过第三方服务再分发"仍可能涉及信息网络传播权与平台条款；
  个人自用风险相对可控，公开订阅链接分发风险显著上升。
- 咪咕：体育/影视独家版权，**不建议任何形式的公开分发**。
- 建议的产品化口径：
  1. 平台源**默认关闭**，作为"高级 → 平台源"里的可选开关；
  2. 订阅里区分"平台线路"，导出时默认不包含，需显式勾选；
  3. 页面和导出里保留"仅供个人学习/自用，内容版权归原平台"的提示；
  4. 不做任何形式的公开频道列表页展示。

## 8. 修订后的"不做清单"

1. B站/抖音/虎牙/斗鱼的直播逆向（不是线性电视、DRM/反爬重、价值低）
2. 账号型私有接口的大规模使用（登录态/设备注册签名）
3. 4K HEVC 平台流（浏览器播不了，需设备签名）
4. 把平台源放进公开频道列表/公开订阅
5. 复制第三方 GPLv3 代码（央视频协议可参考公开描述自行实现；参考项目的频道表同样要自己整理）

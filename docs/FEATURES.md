# 功能对照

图例：✅ 已实现 · 🟡 部分实现 · ⬜ 未实现（路线图）

## 你提出的 15 条

### 1. 每日自动采集 / 测活 / 剔除 ✅

- `.github/workflows/collect.yml` 每天 00:00（Asia/Shanghai）运行，也可手动触发。
- 采集即测活：新线路全部进入当日预算；到期线路按 tier 复检。
- 剔除由状态机完成：失败 1 次移出订阅、3 次判死、14 天后允许复活、90 天季度清理
  （`packages/core/src/aggregate/state.ts`）。
- 单源失败不会中断整轮；失败的源保留上一轮线路，避免上游抖动导致目录清空。

### 2. 多来源、多格式添加 ✅

- 入口：订阅 URL、文件上传、文本粘贴（`packages/worker/src/routes/sources.ts`）。
- 格式：M3U/M3U8、TXT/DIYP、JSON、TVBox `lives`、华为 JSP/HWCTC，自动识别；也可显式指定。
- 添加时先真实抓取并解析，解析不出条目直接拒绝（422 带原因）。
- 支持 `#EXTVLCOPT` 的 UA/Referer/Origin/Cookie，导出时保留。

### 3. 检测中心 🟡

| 子项 | 状态 | 说明 |
| --- | --- | --- |
| 连通性 / 有效数量 | ✅ | HTTP 状态 + 播放列表可读 + 分片可下载；按频道统计 alive/total |
| 播放加载速度 | ✅ | 丢弃 512KB 预热后的稳态速率 + TTFB |
| 分辨率 | 🟡 | HLS master 的 `RESOLUTION` 精确解析；非 HLS 源未知（需 ffprobe） |
| 检测时间 / 按时间筛选 | 🟡 | `lastProbeAt` 落库，频道详情可见「何时测的」；管理端暂未做时间维度筛选器 |
| 成功进有效、失败进失效 | ✅ | 状态机 + 订阅过滤；失效线路保留墓碑，频道详情可查 |
| 自定义分类规则 | 🟡 | 规则引擎（分组/正则/协议/分辨率/速率）已实现并有 API；缺可视化编辑器 |

| 补充：单条探测 / 抽样探测 | ✅ | 后台「检测中心」单 URL 调试；源卡片「抽样测速」一次 8 条 |

### 4. EPG / 台标 / 频道分类 ✅

- 多 XMLTV 源合并、7 天窗口、按 `tvg-id` 与别名匹配到自有频道（`packages/core/src/epg/*`）。
- 频道分组：央视 / 卫视 / 地方 / 港澳台 / 国际 / 4K / 影视 / 体育 / 少儿 / 纪录 / 新闻 / 音乐 / 付费。
- 台标：优先订阅自带 `tvg-logo`，否则按 `tvg-id` 拼接设置里的台标基础地址（默认 fanmingming 图库，可改）。
- EPG 单独出口：`/epg/<token>.xml`，M3U 头部自动写入 `url-tvg`。

### 5. 聚合 / 去重 / 多格式导出 ✅

- 同一频道跨订阅合并，`channelId + urlKey` 去重，评分排序，单源最多 2 条、单频道最多 6 条。
- 出口：`/sub/<token>.m3u`、`.txt`、`.json`、`?format=diyp`、`/epg/<token>.xml`。
- 订阅级过滤：分组、排除分组、频道白名单、最低分辨率、最低速率、协议、地区后缀、是否带 EPG。
- 每轮采集结束预渲染全部订阅到 `out/sub-<id>.*`，Worker 直接流式返回；新建订阅先实时渲染兜底，
  再通过「重建导出」落成静态文件。ETag/304 + 边缘缓存，播放器轮询不产生重复计算。

### 6. GitHub 源加速 ✅

采用你认可的方案：**Actions 拉取 → 自有 KV → 自有域名 + Cloudflare 缓存**。
没有依赖 jsDelivr / ghproxy，避免镜像停摆与中间人可见。
若 Actions 拉取 GitHub 本身不稳定，可在 workflow 里给 `fetchSource` 加代理前缀，但这只影响上行，不影响用户侧。

### 7. 日志 ✅

- 结构化 JSONL：`logs/<date>/<runId>.jsonl`，贯穿抓取、解析、测速、聚合。
- 后台「运行与日志」可按运行查看，含状态、数量、流量、耗时、警告。
- Worker 侧异常进 Workers Logs（`observability.enabled`）。

### 8. iOS 风格 Web ✅

- 手写设计系统（`apps/web/src/styles.css`）：大标题、毛玻璃导航、分组列表、底部 Tab、
  51×31 开关、分段控件、底部 Sheet、明暗主题、安全区适配、减少动效偏好。
- 移动端优先，桌面端自动切换为顶部导航 / 侧边栏。

### 9. 管理后台 🟡

已覆盖：概览、直播源（增删改查/检测/抽样测速/启停）、频道（编辑/别名/启停）、
检测中心（单条探测/触发全量）、订阅（CRUD/预览/轮换 token/复制多格式链接）、运行与日志、设置。

缺口：规则可视化编辑器、批量操作、频道合并的可视化入口（合并 API 已就绪）、趋势图。

### 10. 源信誉分 ✅

- 每次运行更新：`0.65·旧值 + 0.35·(0.72·可用率 + 0.28·平均分)`，抓取失败打折、连续失败扣分。
- 信誉决定复检频率（12h / 72h / 168h）与排序权重；后台以进度条与优质/正常/降权展示。

### 11. 多地区探测 🟡

- 已做：源可标注地区/运营商；线路导出名可带 `（-江苏电信）` 后缀；订阅可关闭后缀。
- 未做：真正的多出口探测。Actions 单出口在海外，无法代表电信/联通。
- 可行扩展：在 workflow 里加 self-hosted runner 矩阵（`runs-on: [self-hosted, jiangsu]`），
  或在 VPS 上跑 `probe` 子命令，把结果 `POST /api/admin/probe-results`。

### 12. 变更 diff 通知 ✅

- 每日对比上一版目录：频道增减、可用线路变化、分组变化、单源失效突增（>40% 且 ≥3 条）。
- Telegram 日报（`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`），后台设置里可开关。
- `notifyWebhook()` 已留通用 webhook 出口，尚未接 UI。

### 13. 众包纠错 🟡

- 前台频道详情每条线路有「报错」按钮，写 D1 `feedback`，按 IP 限流。
- 后台可查看并标记处理。
- 缺口：反馈尚未折算进源信誉分（当前只影响人工排查）。

### 14. 管理后台 Token ✅

- `ADMIN_TOKEN` 只用于登录换取 7 天 HMAC 会话，浏览器不保存主令牌。
- 登录按 IP 限流；runner 用 `x-admin-token` 直连，无需登录。
- 文档提供 Cloudflare Access（邮箱 OTP）双层方案。

### 15. 模块联动 ✅

统一数据主线：**源 → 线路 → 频道 → 订阅**。

- 频道详情看得到每条线路来自哪个源、测速历史、状态；
- 源卡片看得到贡献了多少条、多少可用、信誉分；
- 订阅按频道过滤，引用同一份目录；
- 禁用频道 / 加别名 / 改分组会立即影响下一次导出的选择结果。

## 超出原始需求的实现

- ETag/Last-Modified 条件抓取，源没变时不重复下载。
- URL 归一化去重（忽略 token/expires/sign 等会话参数）。
- 频道别名库 + 模糊匹配 + 频道合并 API。
- 订阅实时渲染（新建订阅立即生效，不需要等下一轮采集）。
- 边缘缓存 + 304，订阅轮询接近零成本。
- 管理操作审计表。
- 登录限流、SSRF 防护、可选 Cloudflare Access。
- 单源「解析检查」与「抽样测速」，不依赖 Actions 即可排障。
- 源健康度与运行历史，失败原因直接显示在源卡片上。

## 1. 按批次做了什么

### Batch 0 · 止血

- **分片桶统一 8**：发布端写 8 个桶、读取端读 16 个桶，导致约一半频道详情/试播读旧分片；改为「8 → 16 → 64 逐级回退」。
- **删源改 paused**：连续失败 5 次的源原来被静默 DELETE，现在保留并暂停，可手动恢复。
- **池快照可见**：`/admin/pool` 显示快照生成时间，并提供「重建快照」。
- **额度护栏**：KV 今日写 ≥920 阻止派发；D1 今日写 ≥90k 阻止派发；Actions 月预算 1600/2000 封顶（0e2e606 进一步做成按天摊平的预算节流，而不是硬卡）。
- **CI**：去掉 push 重复触发；部署步骤加自诊断上报；修复 D1 迁移漂移（0014 已手工应用未登记，导致 0018 永远轮不到）。

### Batch 1 · 源管理（13.5 人日）

- **F0 统一抓取层**：`core/src/source/fetch.ts` 统一超时、24MB 上限、条件请求、重试与错误分类；Worker/runner 共用。
- **S1 源级请求配置**：每源 UA/Referer/Cookie/附加头、`fetch_mode`（直连/Worker 代拉），迁移 0018。
- **S3 自动降级与恢复**：连续失败标 degraded、达到阈值暂停；半开恢复（每 6h 探一个暂停源）；源详情页可手动「重试恢复」。
- **S7 新源导入状态机**：新线路失败 1 次进待复测、第 2 次即终态；只复测一次，失败不再无限轮转。
- **S8 已淘汰生命周期**：保留 30 天、`cleanup-rejected` 清理（先写墓碑）、`revive-batch` 复活、月末低峰抽检；后台按源「复活淘汰」。
- **S9 定时重抓**：多时段 `fetchTimes`；单源按 12/24/72h 三档到期；重抓后对比去重（新增/复用/消失/跳过淘汰），报表落 `state/fetch-report.json` 并在源面板展示。
- **S10 空闲跳过**：没有到期线路/到期的源时不派发任务，任务中心写原因。
- **S2 备用地址链**：`mirror_urls` 最多 5 个，主地址失败按顺序尝试，记录用第几个。
- **S4 解析诊断**：每轮解析结果（类型/条目/字节/警告/是否备用）存 D1，条数较上轮骤降 >30% 标红。
- **S5 健康面板 2.0**：「只看需处理」、贡献频道数、连续失败、最近成功、7 天 sparkline。
- **S6 批量操作与标签**：批量启停/改优先级/打标签/删除，标签筛选。
- **S0 适配器注册表**：m3u/txt/json/tvbox/hwctc 统一注册与 parity 测试。

### Batch 2 · 抓取与代理（8 人日）

- **F1 错误分类**：timeout/network/http_4xx/http_5xx/challenge/not_playlist；只对可恢复类重试；采集层原来 3 次无差别重试删除；源错误显示类别。
- **F4 编码识别**：按 Content-Type/BOM/启发式识别 GBK/GB18030/Big5，解决频道名乱码。
- **F5 每源抓取参数**：超时、镜像并发、请求前延迟。
- **F3 官方保底 + Worker 代拉**：`official` 线路不判死、导出置顶；`fetch_mode=worker` 时由 Worker 拉源正文返回给 runner，不落存储。
- **F6 中继热路径**：发布产出 `state/line-index.json`（单值 1 次 KV 写）；中继不再解析整份 probe.json；Cache API + 内存 60s；旧 `/relay` 收敛为只允许清单；按 token 粗粒度限流与字节配额；转发 Cookie/Origin。
- **F2 订阅级代理**：`direct / playlist / full` 三模式，签名地址绑定「URL+过期+token+模式」（7 天），订阅停用后中继立即 401；后台订阅编辑页可选。

### Batch 3 · EPG（6.5 人日）

- **E2 覆盖率真实口径**：区分「有未来节目 / 已全部过期」，显示节目单年龄与 stale 提示，不再用数组长度假装 100%。
- **E1 未映射工作台**：记录匹配到 `x-` 的节目单频道，后台 `/admin/epg` 可反向绑定；新增「清理 x- 噪声频道」。
- **E4 源优先级与健康**：`epgSourcePriority` 决定合并时的优先级；每次抓取记录每源成功/字节/频道/节目数，EPG 页展示贡献表。
- **E3 官方节目表回退**：合并后仍缺节目的 CCTV 频道，用 `api.cntv.cn` 的 `getEpgInfoByChannelNew` 逐台兜底（tv.cctv.com 页面是 JS 渲染，不能直接解析）。

### Batch 4 · 后台（6 人日）

- **A1 运营事件页**：`/admin/events` 报障 + 审计双 Tab；状态流转、搜索、一键转探测。

## 3. 优化与额度

- **KV**：分片桶统一、line-index 单值（不再每分片读大对象）、EPG 按订阅瘦身、抓取对比报表只写一份；单轮发布实测约 20 次写。
- **D1**：发布批量 UPDATE 去重、`last_seen` 节流、A5 只做聚合显示、迁移记录修复避免重复应用。
- **Actions**：月预算 + 按天摊平、探测间隔 1h→8h、EPG 2 次/天→1 次/天、CI 去重；`usage.ts` 分页修正后用量可见（809/2000 分钟、540 次运行）。
- **Worker CPU**：中继不再解析整份 probe.json；A4 只处理名称；A2 是纯 SQL 聚合。

## 5. 整体改变

1. **数据正确性闭环**：分片、解析诊断、EPG 覆盖率都可核对，不再出现「页面说 100%、实际一半是旧数据」。
2. **源健康闭环**：失败可分类、可降级、可暂停、可恢复、可淘汰、可清理，采集源从「一次性配置」变成「可运营资产」。
3. **交付能力**：订阅从「一条直链」变成「三种代理模式 + 设备级令牌」，换设备/封设备不用再整体轮换。
4. **运营闭环**：报障、审计、失败 TopN、频道编排、规则预览，后台从「配置页」变成「复盘与排障入口」。

## 6. 2026-11-09 增量

- **运行记录一致**：任务派发即写「运行中」占位运行，取消/失败/重试/看门狗同步；抓源汇总消息在任务卡片与运行记录显示同一份。
- **抓取稳定性**：TLS 错误细分为证书过期/域名不匹配/不受信任/握手失败，https 证书失败自动降级 http；每源可选「允许证书错误」；GBK/Big5 编码识别；新源频道（`x-`）线路不再被剪枝。
- **调度**：全局「每 N 天」抓源门控、按源「每 N 天 / 自定义小时」、收藏源置顶排序、分批探测早醒节流（8 小时窗口不变，待测>0 且距上次≥3 小时且每天最多补 1 批）。
- **容量**：发布前 15MB 告警 / 22MB 拒发；`/api/admin/storage/sizes` 查看各产物体积；`state/publish-sizes.json` 记录上次发布体积。
- **可运维性**：`/api/admin/db/migrations` 迁移漂移自检、`/api/version` 返回部署 commit 与时间、`npm run smoke` 线上只读冒烟。
- **订阅**：中继按 token 日配额（超限 429，播放列表回退直连）；设备令牌活跃统计；中继用量按设备/日统计；线路池支持多选批量复活。
- **规则预览**：名称级（Worker，即时）+ 线路级（runner 命令，读真实目录，派发一轮 Actions）。
- **测试**：36 文件 176 例；新增 filters/http/relayQuota/publishSize 等用例。

一句话：**升级前是「能采集、能播放」，现在是「数据可信、源能自愈、订阅可分发、问题能复盘」。**

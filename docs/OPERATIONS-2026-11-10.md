# 运维与功能手册（2026-11-10）

面向日常操作：自定义池、订阅组合导出、预览口径、频道合并撤销、删源清理、线路状态分片与归档、前端冒烟。
管理令牌（`ADMIN_TOKEN`）轮换步骤见 [ADMIN-TOKEN-ROTATION.md](ADMIN-TOKEN-ROTATION.md)（中英文）。
架构与部署见 [ARCHITECTURE.md](ARCHITECTURE.md)、[DEPLOY.md](DEPLOY.md)，历史交接见 [HANDOFF.md](HANDOFF.md)。

## 任务中心

- 任务状态：`scheduled → queued → running → done / failed / cancelled`，同一时间只跑一个 GitHub Actions run。
- **取消**：任务页可取消排队任务；运行中的任务会先取消 GitHub run 再标记 `cancelled`。
- **取消后不会自动重试**：GitHub run 的 `cancelled` 结论不再触发任务重试（以前会重新派发，容易越取消越多）。
- **看门狗**：运行中任务 20 分钟没有心跳会先取消 run、再标记失败；心跳来自 runner 的进度上报（抓源按源开始/完成各报一次）。
- **重试语义**：任务失败/超时重试时，旧任务会标记为 `cancelled`（消息「已由重试任务接替（n/MAX）」），不会再被并回 running。
- **排队锁**：任务派发/修改持有 D1 锁并每 20 秒续租；获取失败会明确报「任务队列暂不可用」，不会无锁继续写入。
- **探测预算**：workflow input / `vars.PROBE_BUDGET` → 后台设置 `probeBudget` → 1200；并发 `vars.PROBE_CONCURRENCY` → 后台设置 → 32。
- **手动 vs 定时抓源**：手动「立即执行 / 抓源」会强制重抓（`force_fetch`），定时任务按 `refresh_hours` 增量跳过未到期源。`paused` 源不参与抓取。
- 单源整体处理超过 `max(120s, fetch_timeout_ms × 2)` 会被放弃并记为该源失败，避免一个卡住的流拖住整批。

## 发布与探测调度

- **每日发布**：设置页「启用每日发布」+「每天发布时刻」（可多个，逗号分隔，北京时间）+「自动发布最小间隔」。只更新 EPG/catalog/订阅，不抓源、不探测。
- **探测后自动发布**：独立开关。探测让线路池发生变化后，按「自动发布最小间隔」触发一次发布；间隔填 0 表示不限制（每次探测后都可发布）；与每日发布互不影响。探测任务完成后会立即检查并触发，不再依赖 5 分钟定时；不满足条件时，任务卡片会直接显示原因（池没更新 / 间隔未到 / 已有发布在跑 / 额度不足）。
- 任务清单分别显示「线路发布 · 定时」和「线路发布 · 探测后自动」两条；后者是事件型任务，没有「下次时间」，右侧显示「探测后」徽章。
- 探测任务（手动或定时）完成后会写回探测计划的「上次运行 / 下次运行」，「下次」按当前仓库模式的模板间隔重算。
- 调度结果统一显示中文：额度不足、已是最新无需发布、没有可发布的产物、有任务正在运行、没有到期的源、暂无到期线路、已创建快照。
- **探测模板**：设置页「仓库模式」分私有 / 公开两套模板，各自可改「每批条数、批次间隔、每日自动派发上限」：
  - 私有默认 1200 条 / 8 小时 / 20 次；公开默认 2000 条 / 2 小时 / 30 次。
  - 调度器、手动派发、任务清单、runner 都按当前模式的模板取参；切换模式或改间隔后，探测「下次时间」会按新间隔重算。
  - 模板只影响探测；抓源、发布、EPG 的频率不受它控制。

## 用量快照

- 用量在 Worker 内刷新，不派 GitHub Actions：GitHub 分钟数走 Actions API；KV/D1 走 Cloudflare 只读分析接口。
- 需要 Worker secret `CLOUDFLARE_API_TOKEN`（账户级「账户分析·读取」）；账户编号与数据库编号已写在 `wrangler.jsonc` 的 vars 里。没有令牌时 KV/D1 保留上一次的值，GitHub 分钟数照常更新。
- 刷新频率：每小时一次（cron `8 * * * *`）；后台「刷新用量」也直接在 Worker 内执行。
- 数据写入 `state/usage.json`，供概览用量面板、Telegram `/usage` 和调度额度护栏使用（护栏只看 GitHub 分钟数）。
- **公开仓库**：只统计本月运行次数，不再估算分钟数（`minutes=0`），概览显示「无上限」，额度护栏跳过 2000 分钟限制；私有仓库仍按分钟数算。
- `POST /api/admin/usage` 只保留兼容，收到外部上报会直接忽略并改走 Worker 内刷新，避免旧工作流写入错误数字；异常分钟数（>50,000/月）按 0 处理。

## 探测按 URL 去重

- 调度批探测与采集的探测阶段会先按「规范化 URL + 请求头」归并：同一 URL（且请求头相同）只真实探测一次，结果回填给所有来源的同 URL 线路。
- 代表线路优先取已可用 / 收藏 / 曾可用 / 最近探测过的；回填只改探测字段（状态、失败次数、分辨率、速度、编码、评分、探测时间），保留各线路的来源、频道、名称。
- 官方保底线路不参与探测，也不会被回填；请求头不同视为不同目标。
- 效果（2026-11-10 实测）：1200 条的一批实际探测 434 个 URL，省约 64%；失败/成功结果会同时落到重复来源。

## EPG 沿用规则

- 发布时如果本轮没有抓 EPG（guide 模式），直接沿用存储的 `state/guide.json`，不再按当前时间重建、裁剪；`generatedAt` 保持上一次抓取时间，不会「看起来永远新鲜」。
- 抓取结果频道数不到旧版一半时，保留旧版指南并记 warning，避免一次失败把节目单清空。
- 恢复方式：重抓一次 EPG（约 3 分钟）后再发布。

## EPG 覆盖、排除分组与建议

- 覆盖率只看「有节目单价值」的频道：默认排除 37 个分组（成人、虎牙频道、斗鱼频道、YY频道、体育-昨天/今天/明天、音乐 MTV/DJ、电影/电视剧、春晚、公告、B站、抖音、iPanda、各类景观/慢直播、山东、IPTV、📺 国内其他、外语频道、音乐、其他频道等），EPG 页可直接编辑这个列表。
- 统计时先过滤再计算，接口返回 `excludedTotal`/`excludedGroups`；「已覆盖」按未来 24 小时内有节目计算。
- 名称宽松匹配：匹配前去掉速度后缀 `(0.001 MB/s)`、前导 `*`、尾部 `-MCP`、画质词（HD/4K/高清等）与标点；只有规范化后唯一的键才参与，避免「综合」类重名误配。
- EPG 源：默认 8 条（含 `epg.112114.xyz`）；某个源失败只记 warning，不影响其他源。
- 自动建议（本地只读脚本，产物 `.tmp/epg-suggestions.md`）：
  - 只对「当前没有未来节目」的频道出建议；同名/包含/相似三类，分数 ≥0.9 为高置信，0.72–0.9 待复核。
  - 规范化后多个频道同名的直接跳过（歧义）。
  - 执行顺序：人工看清单 → `POST /api/admin/epg/bind-bulk`（`{items:[{channelId, alias:epgName}]}`，单次最多 500）→ 重抓 EPG → 再核覆盖率。
  - 绑定会写 D1 别名，务必先确认清单。

## 自定义池

- 入口：线路池页 → 页头「自定义池」（Sheet）。
  - 新建池、改名、删除；点池名 = 只看该池线路，列表表头可排序。
  - 池只是线路集合，删池不影响线路本身。
- 加线路：在列表勾选线路 → 批量条选「加入池」→ 选择目标池。
- 池内线路仍受池快照限制：只有发布快照中可用的线路才会被订阅导出（已淘汰/未入池线路不导出）。

## 订阅选择池与过滤

新建/编辑订阅 → 线路池模式选「自定义池组合」：

- **选择池**：内置池（精品/备用/候选）和自定义池可任意组合；同一线路只导出一次。
- **过滤方式**：
  - `保留原过滤`（inherit）：继续套用订阅保存的频道/分组/分辨率/速度/每频道上限等过滤。
  - `不过滤（全量）`（none）：池内线路全量导出，频道/分组等二次过滤失效（仍会按频道分组、同 URL 去重）。
  - `自定义过滤`（custom）：使用下方当前表单里的过滤字段，随订阅保存。
- `all` 池模式与精品/备用一样从池快照渲染（不再回退到 catalog）。
- M3U 仍按频道名分组：同频道所有线路显示名一致，线路级备注无法在名称里体现（播放器限制）。

## 导出预览口径

新建订阅选择池后，选池下方会显示：

```
本次将导出 N 条线路 · M 个频道；索引可用 X 条 · 池内 Y 条
```

- **索引可用 X**：探测结果为可用的线路数（`index.aliveLines`）。
- **池内 Y**：精品 + 备用 + 候选三个桶的线路总数（快照去重后，可能包含官方线路，所以 Y 可能大于 X）。
- **本次导出 N**：真实渲染器按当前订阅配置生成的结果，已做频道过滤、同 URL 去重、每频道上限裁剪与质量确认。
- 预览接口：`POST /api/admin/subscriptions/render-preview`（未保存表单也能试算）；已保存订阅用 `GET /api/admin/subscriptions/:id/preview`（响应含 `stats`）。

## 频道合并与撤销

- 入口：频道页 →「未识别频道」→ 选择 `x-` 频道与目标频道 → 合并。
- 合并会把源频道的别名、线路和探测状态迁移到目标频道，然后删除源频道。
- **撤销**：同一面板底部「最近合并」列出每次合并，点「撤销」可恢复频道的名称/别名，并把该次迁移的线路和探测状态迁回。
- 撤销只回迁该次合并记录的线路 key，不会影响目标频道原有线路。
- 有任务正在运行时合并会被拒绝（409），避免与抓取/发布互相覆盖；这是软保护，不是严格互斥。
- 批量合并：`POST /api/admin/channels/merge-duplicates`（`{dryRun:true}` 默认）；只并带速度/画质噪声的副本，一次读取线路状态、一次写回（KV 约 9 次，而不是每组 9 次）；执行前要求没有运行中任务，来源频道删除后名称从合并快照回填。

## 删源与孤立线路

- 删除采集源后，它的线路默认仍留在池中（可播放、可导出），最长保留 `LINE_RETENTION_DAYS`（默认 30 天）。
- 需要立刻清理时：线路池页 → 页头「清理已删源」→ 确认。
  - `GET /api/admin/pool/orphans`：按来源聚合的孤立线路（来源已不存在）。
  - `POST /api/admin/pool/orphans/cleanup`：执行清理；可带 `sourceId` 只清某个来源。
- 清理默认跳过仍可用的线路（alive），只清已淘汰/待测等；`GET /api/admin/pool/orphans` 会返回 `aliveKept` 计数。

## 源卡片口径

- 「线路」只统计**可探测线路**：频道存在且协议不是 rtsp/udp；`可用 + 待测 + 待复测 + 已淘汰` 应精确等于它。
- 卡片下方会提示「另有 N 条未匹配频道/不可探测」，这些线路计入源文件解析数，但不进入四个状态桶，也不参与探测。
- 变化值 `+N / −N` = 「当前值 − 该源本次抓取完成时写入的基线」，两张卡片用同一口径；刚完成抓取时通常全为 0，之后探测/清理带来的变化会立即体现。

## 容量、归档与告警

- 存储大小见「设置 → 容量」或 `GET /api/admin/storage/sizes`。
- **线路状态分片**：`state/lines.json` 已拆成 `state/lines-manifest.json` + `state/lines-0.json`…`lines-7.json` 共 8 片，每片 gzip 存储；读取方（runner / Worker）优先读 manifest，没有 manifest 时自动回退旧的单文件。线上 33k 条约 19MB → 8 片合计约 4.4MB（每片 0.5–0.6MB），远低于 KV 25MB 单值上限。发布成功写入分片后会删除旧的 `state/lines.json`。
- **阈值**：单个产物 15MB 告警、22MB 发布阻断；EPG 有单独的 24MB 保护。
- **大产物读取**：管理端产物接口先查 `state/publish-sizes.json`；超过 2MB 直接流式转发（`application/octet-stream`），不再整份读进内存；≤2MB 保持原 content-type。
- **产物重写**：>2MB 产物的 ETag 带时间戳，每次发布都会重写，避免「字节数相同但内容不同」不更新。
- **自动归档**：线路原始体积（未压缩 JSON）超过 12MB 时，runner 会把「已淘汰且 30 天（线路保留期）没有探测记录」的线路移入 `state/lines-archive.json`（归档最多 20,000 条，按时间倒序保留）。分片 + gzip 上线后这一步通常只是兜底，不再承担主要瘦身职责。
  - 归档只针对失效线路，活跃线路不会被动。
  - 归档文件同样计入存储大小，可在设置页看到。
- **归档回读**：线路池页「恢复归档」（`GET /api/admin/pool/archive`、`POST /api/admin/pool/archive/restore`）；恢复的线路置为「待测」，等下一轮探测重新评估。
- **诊断**：`GET /api/admin/pool/line-stats` 返回线路总数、原始字节数、按状态/协议分布和「dead 超 30 天」数量，不用下载整份 `lines.json` 就能判断容量问题。
- **告警**：概览页在任一产物超过 15MB 时显示橙色容量告警，并链到设置页。
- **快照保留**：只保留最近 3 个快照目录；每次 cron / 创建快照最多删 40 个 key，避免一次打满 KV 写额度。
- **KV 写保护**：单日写入上限 900 次；达到上限后暂停新任务与产物写入，UTC 00:00 自动恢复。

## 频道详情与台标来源

- 线路默认顺序：收藏 > 精品池 > 备用池 > 候选池 > 评分；`#1` 是当前首选，播放失败会自动切下一条。默认排序下 `#1` 带「首选」徽章，筛选区下方有排序说明。
- 台标来源优先级（`packages/runner/src/pipeline/publish.ts` 的 `logoForSeed`）：
  1. 频道已存的显式台标；
  2. 频道没有台标且没有 `tvgId` 时，用线路自带的台标；
  3. 否则用台标包 / 文件名推断。
- 数据库写入只补空（`COALESCE`），已有台标不会被来源线路覆盖。
- 公开频道详情接口返回 `logoFromKey`；命中时对应线路显示「台标供体」徽章。台标来自台标包或已存台标时没有供体徽章。
- 回归测试：`packages/runner/test/build.test.ts` 的 `channel logo provenance` 两例。

## 播放限制与提示

- `rtsp/rtmp/rtmps/udp/rtp`：浏览器无法播放，播放器直接提示换线路。
- H.265/HEVC：Chrome/Edge 通常不支持，播放前提示改用 Safari 或 VLC（检测到 `hvc1/hev1/hvc` codec 时显示）。
- 中继 403/502：提示「源站拒绝中继访问（通常限制地区/IP）」，不是 Worker 故障。
- HTTP 线路在 HTTPS 页面会被拦截，播放器会提示可走中继。

## 源重叠与质量

- 入口：采集站页头「重复线路」（`GET /api/admin/sources/overlap`）。
- 口径：按规范化 URL 归并；同一 URL 被多个来源收录只算一条线路。
  - **重复**：该来源与其他来源共享的 URL 数；**独有**：只在该来源出现的 URL 数。
  - **重复占比** = 重复 / 该来源线路数；**最早收录** = 该来源最早出现某个重复 URL 的次数。
- 用途：重复占比高、独有少的源通常是镜像；删除前先看独有数，删源后记得清理孤立线路。
- 线上样例（2026-11-10）：48,022 条线路 / 32,853 个 URL，10,121 个 URL 被多源收录（涉及 25,284 条线路）；多数大源重复率在 96% 以上。

## 监控告警

Worker 在每次 5 分钟排程里跑 `runMonitor`（`packages/worker/src/lib/monitor.ts`）：

- **池快照过期**：`state/pool-stats.json` 超过 26 小时未更新 → Telegram 提醒。
- **可用线路骤降**：相邻两轮可用线路跌超 50%（且上轮 ≥100）→ 提醒。
- **线路总数骤降**：相邻两轮总数跌超 50%（且上轮 ≥1000）→ 提醒。
- 同类告警 6 小时内不重复；未配置 Telegram 时静默。阈值常量：`STALE_MS`、`ALERT_GAP_MS`。

## 页面状态约定

- 查询失败统一用 `QueryError`（标题 + 错误信息 + 「重试」按钮），不再只显示一行灰字；已覆盖采集站、线路池、订阅、EPG、概览。
- 空态用 `EmptyState`，标题说明「为什么空」，不要用「加载失败」冒充空数据。

## 发布与 CI 门禁

- 部署流水线先跑 `npm test`、再跑 `npm run typecheck`；两者都会执行，任一失败就不部署。
- 部署成功后自动跑 `scripts/smoke.mjs`；失败会把日志摘要写入运营事件（`ci-deploy`）并标记 run 失败。
- `packages/runner/**`、`scripts/**` 的变更也会触发部署流水线（以前只校验 worker/core/web）。

## 国内代理与补测

- 入口：运营发布 →「国内代理」。支持手动添加、多格式导入（URI、`host:port[:user:pass]`、Clash YAML、sing-box JSON、Base64、Quantumult X / Surge / Loon 行）、文件上传/拖拽、从剪贴板读取、启停、上下移、设为当前、删除。
- 协议：HTTP / SOCKS5 可测活；`ss`/`vmess`/`trojan` 等导入后灰显「需内核」，一期不启用。密码 AES-GCM 加密存储，接口只返回掩码。
- 当前代理 = 默认顺序里第一个启用的非内核节点；点「设为当前」会把它提到最前。
- 测活：5 个目标按顺序试（`ipinfo.io/json`、`myip.ipip.net`、`baidu.com`、`api.ip.sb/geoip`、本站 `/api/version`），单目标 5 秒、总 20 秒；记录延迟、出口 IP、国家、ASN。hy2/tuic 属于 UDP，当前环境直接跳过并标注「UDP 不可测」。
- 拉订阅：可选「Actions 直连」或「通过代理」；后者按最近成功节点依次尝试。注意 Actions、Worker 都在机房出口，国内代理只代表该节点出口，无法覆盖所有地区/运营商。
- **代理订阅**：订阅链接拉取成功会自动保存为「链接」订阅；文件导入可填名称保存为「文件」订阅（不参与定时刷新）。订阅卡片支持刷新、每订阅测活、定时自动刷新（开关 + 默认 24 小时，可改 1–168 小时）；删除订阅时可选：删除全部节点 / 保留测活成功过的节点 / 保留全部节点仅删记录。

## 定时测活与国内补测

- 自动测活是开关：关闭时不产生定时任务；开启后二选一——固定间隔（1–24 小时）或自定义时段（`HH:mm` 列表）。
- 定时测活与补测前预检互相独立：补测开始前总会预检当前代理，失效则全池测活并选第一个可用。
- 补测开关打开后，主探测或补测任务完成会触发一次检查并派发 `cn-probe`；条件：开关开、额度未阻塞、没有排队/运行中的补测。
- 补测只重测「已淘汰/疑似且 24 小时未补测」的线路，每批默认 200 条；成功则置为可用并写入国内可达字段（延迟/代理/时间）。
- 订阅导出默认「包含国内可达线路」；关闭后导出会过滤 `cnReachable=true` 的线路。
- 任务中心会显示「代理测活 · 定时」「国内补测 · 探测后自动」卡片，运行记录同样有。

## 内核节点（ss / vmess / vless / trojan / hy2 / tuic）

- 代理导入时，http/socks 之外的协议会标为「需内核」并保留原始配置（Clash 原文、sing-box JSON 或分享链接），密码用 AES-GCM 加密存库。
- 测活、拉订阅、国内补测优先用普通代理；普通代理都不可用时才启动内核节点（mihomo）。
- 内核版本固定（默认 `v1.19.9`，可用 GitHub 变量 `MIHOMO_VERSION` 覆盖）；二进制缓存在 `.tmp/mihomo`，工作流用 `actions/cache` 复用；可设置 Secret `MIHOMO_SHA256` 校验下载内容。
- 单个内核节点测活会临时启动进程、通过本地 SOCKS 端口探测，结束后关闭；批量测活单批最多 20 个、并发 3。
- 任务消息会标注「内核」；失败时看 `mihomo.log`（下载 / 解压 / 启动 / 探活哪一步失败）。
- 国内补测选中内核节点时只启动一次，整批共用该本地端口。
- **国内中转**：内核测活会从已测活成功的普通代理里按延迟取前 3 个作为 hop，逐级递补；都失败才回退直连。采集站的节点若限制机房出口，这一层能救回一部分。

## 合并频道

- 采集站 → 源「过滤」→「合并到频道」+「频道分类」；保存时立即写入频道库（`x-mc-<sourceId>`），该源所有线路都会归到这个频道。
- 订阅与导出 →「合并频道导出」：跟随普通频道 / 不导出 / 只导出合并频道；每频道上限 0 表示不限。
- 分组默认「影视」；频道名建议用「虎牙直播」「斗鱼直播」这类平台名。
- 分类以频道库为准：发布快照与订阅导出都会用「频道分类」覆盖线路自带分组；修改分类后重新拉订阅即生效，前台频道页要等下一次发布。

## 纯数字名称过滤

- 采集站 → 源「过滤」→「过滤纯数字频道名」，默认开；只影响后续抓取入库，不删除已有频道/线路。
- 即使过滤规则为空也按默认开执行；需要保留数字名称时对单个源关闭。
- 判断的是解析后的频道名（去掉首尾空格），`1`、`106` 会被丢弃，`CCTV-1` 不会。

## 任务名称映射

- 任务类型中文名统一由 `packages/core/src/taskLabels.ts` 提供；前台、概览、检测中心、运行与日志共用一份，新增任务类型只改这里。

## 名称即频道与分类同步

- 源的「合并到频道」留空、只填「频道分类」时，每条线路名都会成为一个独立频道（id 以 `x-` 开头），并统一归到该分类。
- 发布前会自动 `POST /api/admin/channels/ensure` 补建缺失频道（分批 50、单次上限 20,000）；发布目录只收录「至少 1 条存活线路」的频道。
- 空频道清理会保留仍被线路引用的频道，只删既没有线路、也不在活跃目录里的。
- 改分类：保存源设置会同步该源已有频道；也可以 `POST /api/admin/channels/bulk-group`（指定频道 id）或 `POST /api/admin/sources/:id/apply-group`（带 `dryRun=1` 预演）批量应用。
- 分类以频道库为准：发布快照与订阅导出都使用 D1 的 `group_title`，自定义分类不会再被归到「地方」。

## 频道分组开关

- 入口：频道页 → 分组筛选选中一个分组 → 下方出现「整组：禁用本组 / 启用本组」。
- 禁用只改 `enabled`，不删频道、不动线路；发布一次后前台和订阅不再出现，重新启用并发布即恢复。
- 接口：`POST /api/admin/channels/bulk-enabled`，可传 `{group, enabled}` 或 `{ids:[...], enabled}`；只写状态实际变化的行，上限 5000。
- 典型用法：成人内容统一归到「成人」分组并保持禁用；需要时在后台整组启用。

## 规则匹配字段

- 「线路名包含」匹配线路名称（`line.name`）；「频道名包含」匹配频道名称（`channel.name`）；「线路分组」精确匹配线路自带分组（去空格后比较）。
- 三个条件同时填写时必须全部满足；前两个支持正则表达式。
- 多条规则命中同一频道时：频道级动作（改分组/改名/换台标）每个频道只结算一次——`priority` 数值大的生效；同优先级按规则 id 字典序小的生效。排除与加标签仍逐线路生效。

## D1 / KV 写入配额

- 每日额度：D1 10 万行写入、KV 900 次写（put/delete 分开计数，每小时按 Cloudflare 官方数字校准）。
- 已做写入去重：`channels/ensure` 与 `sync/source-counts` 只写真正变化的行；`sync/channels` 先对整份频道列表做 SHA-256，与上次一致时直接跳过，不产生 D1 读写；别名只在新频道插入时写一次，不再每次同步重复插入。
- 大批量操作（批量改分类、清理频道、发布）前先看概览用量；发布一次的写入量大致等于当次变化的频道行数。

## 已知限制

- 订阅导出的「2280 vs 2218」不是错误：索引统计探测可用线路，池快照按质量确认和每频道上限筛选，导出再按订阅过滤；三个数各自口径不同。
- M3U 播放器按显示名分组，同频道线路不能单独备注。
- EPG 覆盖率受公共节目单源限制（地方台缺节目单、`51zmt` 地址失效）。
- GitHub Actions 出口对部分国内域名不稳定，必要时把该源切到 `worker` 代拉。
- 合并频道的「任务运行中拒绝」是软保护，两个合并请求并发仍可能交错。
- >2MB 产物以 `application/octet-stream` 流式返回（内容正常，只是不再带精确 content-type）。
- Worker 代拉暂不遵守单源的「允许证书错误」设置：证书过期/自签的源代拉会报 526，此时用直连抓取（Actions）即可。
- 国内代理的登录/订阅拉取能力受对端风控影响，换 UA/请求头只能绕部分限制，不能保证。
- 公开仓库「标准运行不计费」是 GitHub 当前政策，平台以后调整时以实际账单为准。
- 私有/公开探测模板只影响探测，不会改变抓源、发布、EPG 的调度。
